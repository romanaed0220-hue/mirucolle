## C. 建议的实现路线（Claude Code 可按此推进）

1. **工程骨架与发布链路**：静态前端工程（多文件或 Vite），手机优先布局（约 390px 宽、safe-area），底部导航 記録 / 収集 / つながり + 侧边栏 マイページ，Lucide 图标，CSS 变量主题；配好 `dev` / `main` 分支和 GitHub Pages 自动发布（流程见 `05-dev-and-test-workflow.md`）。**先出 2–3 个视觉风格方向给用户选，再定 UI。**
2. **記録**：相机/选图 → 画布上手指描线（Canvas、禁止触摸滚动），可调颜色/粗细 → 命名 + 在形内画细节 → 保存形（只存路径/形数据，不存原图到收藏）。
3. **収集**：以"形"为元素，Matter.js 玻璃瓶物理交互；陀螺仪（iOS 授权）+ 触摸回退；数据存本地并带版本号。
4. **つながり**：逐张翻牌；"先に描く、それから見る"流程（未描前不展示他人解释）；含"尚无人描过"的卡片 + 「あなたには何に見えますか？」；官方お題恒为第一张；用预置示例数据模拟他人。
5. **チャレンジ**：官方お題发布（本地配置文件模拟运营方）；参加后记录页入口消失；作品进入裏世界（极光配色，横滑/网格浏览过去主题）；参加得点。
6. **点数商店**：笔色粗细、瓶子外观、主题色、补参加过去挑战。
7. **月間ピックアップ**：基于本地数据（或示例数据）"最多被再描"的一张，滑到时彩虹边框/弹出演出，**任何位置不显示数字**。
8. **测试准备**：首次引导里显式说明"先描，再看"和"数据只存在本机"；"导出我的使用记录"按钮（JSON，不含照片）；问卷链接位；manifest（添加到主屏幕），不使用 service worker 缓存。
9. **真机验证**：在 iPhone Safari 和安卓 Chrome 上用部署后的 HTTPS 网址各跑一遍（描线、相机、陀螺仪）。

## D. 验收要点
- 全 App 找不到任何排名、点赞数、被采用数。
- "先描、后看"在引导与界面文案里都有明确出现。
- 个人收藏页只出现被遮罩的形（无背景、无卡片框）；完整照片只在详情里出现。
- 官方お題在 feed 第一张、且参加后记录页按钮消失。
- 月度精选只有演出，无数字。
- 在手机真机、部署后的 HTTPS 网址上，描线、拍照、瓶子交互都能正常用（陀螺仪被拒绝时有触摸回退）。
- 更新一次版本后，已有的收藏数据不丢（存储有版本号和迁移）。
- 主题色可切换（CSS 变量），裏世界和月度精选演出不依赖硬编码颜色。
